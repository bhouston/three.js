## Direct answers

- **AO uses surface MRTs.** `webgpu_postprocessing_ao.html` writes packed view normal and velocity plus depth, then GTAO/SSAO consumes depth+decoded normal. Its beauty pass receives AO through `builtinAOContext`. It does **not** attach the prepass depth to beauty. Both geometry passes rasterize their own depth. VXGI/VXGI Sponza and screen-space shadows (the file named `sss`) use the same two-geometry-pass pattern, with GI/shadow material context injection.
- **No true depth-only prepass followed by shared-depth overdraw rejection was found.** Search covered every `examples/webgpu*.html` for `depthPass(`, `depthTexture:`, depth texture assignment, `autoClearDepth`, explicit `depthFunc`, `count: 0`, and `colorWrite = false`. The only shared depth constructor is deferred→transparent composition. Other `colorWrite=false` uses are clipping stencil and volume fire shadow rendering, not this pattern.
- `webgpu_volume_lighting_traa.html` invokes `depthPass(scene,camera)` and samples its depth into `volumetricMaterial.depthNode`, but its later scene pass has fresh depth. Furthermore `depthPass` at this revision only changes the *returned node scope*. It still creates the default color target, does not set `count:0`, disable lighting/color writes, or install a depth override material ([PassNode constructor/setup/factory][pass-ctor], [pass-setup], [pass-factory]). Calling that hardware depth-only is unsupported.
- **The real shared-depth example is `webgpu_deferred.html` L217–222:** opaque surface MRT depth is passed as `depthTexture` to transparent-only geometry with `autoClearDepth:false`. This avoids transparent draws appearing in front of opaque occluders. The opaque pass is an MRT geometry producer, not a cheap depth prepass. Transparent material retains the default `LessEqualDepth`, depth test/write enabled; no `EqualDepth` prepass shading arrangement is selected.

## Shared conventions and format caveats

`pass()` constructs a `RenderTarget` with `HalfFloatType` and default RGBA color attachments; depth is a separate default `DepthTexture` (`DepthFormat`, `UnsignedIntType`, nearest). Named `getTexture(name)` attachments clone the first color texture. A `vec2` logical output therefore does **not** by itself make an RG-format physical attachment. Unless explicitly changed, color min/mag filtering is linear; none of the primary AO/VXGI/SSR/SSGI examples overrides that. `webgpu_mrt` and direct MRT/readback examples do use nearest. All scene passes clear color/depth/stencil by default; material depth compare defaults to `LessEqualDepth` (the backend reverses the comparison when reversed depth is enabled). Samples inherit `renderer.samples` during pass setup. [Defaults][pass-ctor], [attachment allocation][pass-allocate], [clear defaults][pass-clear], [sample/type setup][pass-setup], [RenderTarget defaults][rt], [depth defaults][dt], [material defaults][material].

**Important source caveat:** AO and both VXGI files set the *first* `output` normal attachment to `UnsignedByteType`. `PassNode.setup()` unconditionally resets `renderTarget.texture.type` to `renderer.getOutputBufferType()` (default HalfFloatType). Thus the RGBA8 comment/assignment may not survive pass graph setup. Non-first `normal`/`diffuseColor` attachments are unaffected by that line. The matrix reports declared intent and this override separately; runtime inspection is required before asserting GPU byte counts. A helper must address/avoid attachment-zero overrides.

`packNormalToRGB` and `unpackRGBToNormal` are affine transforms only, without normalization ([Packing.js L13–23][packing]). Their affine part commutes with interpolation, but the result need not be a unit vector and interpolation still blends different surfaces; this cannot be generalized to octahedral codecs. Octahedral/semantic views need a deliberate nearest or decode-aware filtering policy. Data attachments use the default no-color-space interpretation; display transforms used for Inspector presentation do not make normals sRGB data.


Normal semantics: ordinary fragment MRT `normalView` calls the material setupNormal context, including normal mapping; `normalViewGeometry` is the distinct geometric/vertex normal node. A field called merely 'normal' hides this distinction. See [Normal.js L95–119](https://github.com/bhouston/three.js/blob/d7848108d3c2b93c322b99fe41b4c3dbafa620b5/src/nodes/accessors/Normal.js#L95-L119).

Recommend migration order: **(1)** AO plus VXGI pair to factor repeated normal/depth/motion setup while preserving lighting contexts; **(2)** SSR and SSGI pair to prove codecs/shared channels and later effect outputs without changing effect signatures; **(3)** TRAA/TAAU as minimal/resolution/history compatibility tests; **(4)** SSR denoise and volume lighting as explicit history/encoded-normal/depth ownership stress cases. Keep MRT/direct readback examples explicit as baseline teaching and escape-hatch examples; do not retrofit legacy renderer passes.

## Temporal and normal contracts that a surface helper cannot assume

TRAA owns resolve and persistent history targets, with a separate history DepthTexture. Before the render pipeline it saves the unjittered camera projection and assigns it to its velocity node, then offsets camera view; after the pipeline it clears the offset/projection and advances Halton index ([TRAA L282–330][traa-jitter], [setup events L428–459][traa-events]). Reprojection converts current-minus-previous NDC motion to UV with `(0.5,-0.5)` then subtracts from current UV ([TRAA L527–532][traa-motion]). Resize seeds history from current beauty; depth copy is gated to matching drawing-buffer dimensions ([TRAA L366–409][traa-history]). TAAU separately stores output-resolution color/lock histories plus input-resolution previous depth ([TAAU L155–188][taau-history]); metadata/lifetimes belong to each temporal algorithm, not a single scene G-buffer.

Velocity computes current clip/NDC minus previous clip/NDC ([VelocityNode L111–181][velocity]). There is per-camera matrix state and per-object previous model matrix state; skin and instance previous positions are explicitly implemented ([Skinning L248–276][skin], [Instance L209–229][instance]). `Morph.js` imports/updates positionLocal but contains no positionPrevious/previous morph-weight tracking ([Morph L179–253][morph]); do not promise correct morph-deformation motion without a separate fix/test. Custom displacement also requires explicit previous deformation consistency. Multiple cameras/XR, two temporal jitter owners, and different producer resolutions require instance-scoped policy and tests; no globally mutable semantic name solves these.

The fork's SSR temporal and recurrent denoise accept a normal texture node, then hard-code `unpackRGBToNormal(...rgb)` ([TemporalReproject L231–239][temporal-normal], [RecurrentDenoise L435][denoise-normal]). AO/SSR/SSGI, by contrast, already accept decoded ordinary sample nodes. To make octahedral normal storage interchangeable for those fork denoisers, either add a decoded-normal API with an explicit history contract or insert a conversion pass; changing their algorithm is outside the smallest surface-layout helper. Recurrent history has its own raw/temporal/filtered/age contracts; reuse of a generic alpha channel is unsafe.

## Legacy WebGL AO comparison

Current filenames are exactly `webgl_postprocessing_gtao.html`, `webgl_postprocessing_ssao.html`, `webgl_postprocessing_sao.html`. All create an EffectComposer `RenderPass(scene,camera)` then their AO pass ([GTAO example L94–98][legacy-gtao], [SSAO example L109–112][legacy-ssao], [SAO example L125–127][legacy-sao]). These examples render normal/depth separately using MeshNormalMaterial override passes; they do not reuse that depth for later beauty geometry. These are sampled geometry inputs for screen-space effects, with fullscreen compositing, not overdraw prepasses.

- `GTAOPass.setGBuffer(depthTexture,normalTexture)` explicitly imports caller-owned separate textures, disables its internal scene normal/depth render, and supports depth-only import with normal reconstruction. Without imports it creates nearest HalfFloat normal target + packed depth-stencil `UnsignedInt248Type`; only `_renderGBuffer` decides whether the override render occurs ([GTAOPass L295–349][gtao-hook], [L506–525][gtao-render]). This is an existing reuse hook, not a resource graph or shared depth attachment contract.
- `SSAOPass` and `SAOPass` allocate their normal target, depth-stencil texture, AO/blur resources internally and unconditionally render scene with MeshNormalMaterial each render. No equivalent public `setGBuffer` exists in these classes ([SSAOPass L151–195][ssao-target], [L282–287][ssao-render], [SAOPass L111–136][sao-target], [L245–246][sao-render]). They expose ordinary class properties/uniforms that could be wired manually, but that is not a documented equivalent ownership/scheduling hook.
- These legacy passes own their internal resize/dispose paths; imported GTAO textures remain caller owned. Nothing here justifies requiring a TSL abstraction for WebGLRenderer.

## Design evidence from this matrix

A small configuration function returning `{ pass, depth, normal, velocity, roughness, ... }` as ordinary nodes can remove the repeated allocation/type/decode/Inspector scaffolding. A thin codec/layout descriptor is justified if interchangeable channel packing is a demonstrated goal: SSR roughness/metalness separate vs normal/base alpha packing is already present. Freeze layout before shader compilation, allocate a shared attachment once when any of its fields is requested, and write all agreed channels of that attachment. Consumers should retain node references to immutable raw/temporal/filtered outputs. A scope-local return object is sufficient for incremental outputs when each producer returns a *new* object; a mutable global `reflection` property risks silent retargeting. Surface semantic data and temporal resource lifecycle differ across these examples and should stay separable.

This source audit does not establish complete scheduling, cycle rejection, transient pruning, GPU aliasing, history validity, or attachment removal; the main core investigation must establish those. In particular, depth sampling is a pass-node graph edge, while attaching a raw DepthTexture to another pass is not by itself an explicit producer edge.
